## 4. Consulta executada (somente leitura)

```sql
with alvo(ordem, assinatura) as (
  values (1, 'public.current_auth_user_id()'),
         (2, 'public.current_app_user_id()'),
         (3, 'public.user_has_unit_access(uuid)')
)
select a.assinatura                                                   as alvo,
       p.oid is not null                                              as existe,
       (select count(*) from pg_proc p2
         where p2.pronamespace = 'public'::regnamespace
           and p2.proname = split_part(split_part(a.assinatura, '.', 2), '(', 1)) as qtd_sobrecargas,
       pg_get_function_result(p.oid)                                  as retorno,
       l.lanname                                                      as linguagem,
       p.provolatile                                                  as volatilidade,
       p.prosecdef                                                    as security_definer,
       p.proconfig                                                    as config,
       p.proleakproof                                                 as leakproof,
       p.proparallel                                                  as parallel,
       pg_get_userbyid(p.proowner)                                    as dono,
       position(chr(13) in p.prosrc) > 0                              as corpo_tem_cr,
       md5(replace(p.prosrc, chr(13), ''))                            as md5_prosrc_sem_cr,
       md5(btrim(regexp_replace(regexp_replace(replace(p.prosrc, chr(13), ''),
                                               '--[^\n]*', '', 'g'),
                                '\s+', ' ', 'g')))                    as md5_prosrc_logico,
       md5(replace(pg_get_functiondef(p.oid), chr(13), ''))           as md5_functiondef_sem_cr,
       position('request.jwt.claims'    in p.prosrc) > 0              as le_formato_novo,
       position('request.jwt.claim.sub' in p.prosrc) > 0              as le_formato_antigo,
       position('candidato'             in p.prosrc) > 0              as tem_cte_candidato,
       md5(obj_description(p.oid, 'pg_proc'))                         as md5_comentario,
       left(obj_description(p.oid, 'pg_proc'), 60)                    as inicio_comentario,
       has_function_privilege('anon',          p.oid, 'EXECUTE')      as exec_anon,
       has_function_privilege('authenticated', p.oid, 'EXECUTE')      as exec_authenticated,
       has_function_privilege('service_role',  p.oid, 'EXECUTE')      as exec_service_role,
       coalesce(array_to_string(p.proacl, ' | '), '(ACL nula: padrao = EXECUTE para PUBLIC)') as acl_bruta
from alvo a
left join pg_proc p     on p.oid = to_regprocedure(a.assinatura)
left join pg_language l on l.oid = p.prolang
order by a.ordem;
```

### 6.3 ACL — observada, não é divergência da 067

A ACL de staging é **explícita**:
`=X/postgres | postgres=X/postgres | anon=X/postgres | authenticated=X/postgres | service_role=X/postgres`.
Na referência local ela é **nula**, o que equivale a `EXECUTE` padrão para PUBLIC.

- `=X/postgres` é `EXECUTE` para **PUBLIC**; as entradas de `anon`, `authenticated` e `service_role`
  são compatíveis com os **privilégios padrão do Supabase** para funções do schema `public`.
- **A `067` não emite `grant` nem `revoke`.** O `EXECUTE` para PUBLIC e as entradas explícitas
  **não** são causados por ela e **não** contam como divergência dela.
- Para o RLS, o que importa é `authenticated` poder executar `user_has_unit_access` e
  `current_app_user_id`: **`exec_authenticated = true`** nos dois. Como ambos são `SECURITY
  DEFINER`, a `current_auth_user_id` é executada pelo dono dentro da cadeia.
